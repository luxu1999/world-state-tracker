# 🌍 世界状态追踪器 (World State Tracker)

> SillyTavern 角色扮演扩展 — 自动追踪世界状态，让 AI 记住每个角色的位置、状态、记忆与好感度。

## ✨ 功能

- 🤖 **自动解析 `<S-summary>`** — AI 回复末尾的状态标签，自动提取并存储
- 📋 **可折叠状态卡片** — 每条 AI 消息下方显示当前世界状态，点击折叠/展开
- ✏️ **手动编辑** — 点击任意字段直接修改，立即生效
- 🔄 **静默总结** — 每次 AI 回复后，后台调用 `generateQuietPrompt` 重新评估状态（不显示在聊天中）
- 💾 **localStorage 持久化** — 按聊天文件独立存储，切换聊天不混淆
- 📖 **世界书集成** — 自动读取世界书角色列表和好感度系统
- 🧠 **智能记忆管理** — 重要记忆自动评分排序，每人最多 6 条，每条 ≤70 字
- 🔇 **隐藏 S-summary** — 从消息显示中移除原始标签，保持界面整洁
- 👩 **仅追踪女性角色** — 所有字段（在场/不在场/状态/记忆等）仅记录女性角色
- 🚫 **排除用户角色** — 用户扮演的角色（即使为女性）不出现在任何追踪字段中
- 🛡️ **代码层安全网** — 自动清理在场/不在场矛盾，剔除泛称条目（七神/众人等）

---

## 📥 安装

1. 下载 `world-state-tracker` 文件夹
2. 放入 SillyTavern 的 `data/default-user/extensions/` 目录
3. 在酒馆扩展面板中启用「世界状态追踪器」
4. 重新加载酒馆

> ⚠️ 如果你在使用旧版本预设中的 Regex 脚本或提示词注入来做状态追踪，请在启用本扩展前关闭它们，避免重复注入。

## 🧠 工作原理

### 数据流

```
AI 回复（含 <S-summary>）
    │
    ▼
┌──────────────────────────────────────┐
│  1. DOM 监听 CHARACTER_MESSAGE_RENDERED │
│     提取 <S-summary> 内容 → parseSummary() │
│     解析为结构化状态对象                   │
└──────────────────┬───────────────────┘
                   ▼
┌──────────────────────────────────────┐
│  2. 合并状态 mergeState()               │
│     新值覆盖旧值，记忆合并去重排序          │
│     过滤用户扮演角色 filterUserFromState() │
└──────────────────┬───────────────────┘
                   ▼
┌──────────────────────────────────────┐
│  3. 保存到 localStorage                │
│     key = wst_state_<聊天文件名>        │
└──────────────────┬───────────────────┘
                   ▼
┌──────────────────────────────────────┐
│  4. 注入状态卡片到消息 DOM               │
│     蓝色头部 + 粉色内容区，可折叠          │
└──────────────────┬───────────────────┘
                   ▼
┌──────────────────────────────────────┐
│  5. 下次发送前 injectStateToPrompt()    │
│     通过 setExtensionPrompt() 注入状态到  │
│     AI 的 prompt 上下文                  │
└──────────────────┬───────────────────┘
                   ▼
┌──────────────────────────────────────┐
│  6. AI 回复后 triggerSummarize()       │
│     通过 generateQuietPrompt() 静默总结   │
│     （不显示在聊天中，仅更新状态）           │
└──────────────────────────────────────┘
```

### 事件驱动

| 事件 | 行为 |
|------|------|
| `CHARACTER_MESSAGE_RENDERED` | 扫描新消息提取 `<S-summary>`，触发静默总结 |
| `MESSAGE_SENT` | 注入世界状态到 AI Prompt |
| `CHAT_CHANGED` | 切换聊天 ID，重新扫描 |
| `MESSAGE_UPDATED` | 消息编辑后重新扫描 |
| MutationObserver（兜底）| DOM 变化时扫描（事件系统不可用时） |

## 📋 状态字段

| 字段 | 说明 | 格式示例 |
|------|------|----------|
| 时间 | 当前剧情时间 | 2024年7月15日14时30分 |

| 重要记忆点 | 改变人生的重要事件 | 琴：初次与主角并肩作战\|被主角从深渊教团手中救下 |

## 🔧 AI Prompt 注入规则

本扩展在每次 AI 生成前通过 `setExtensionPrompt()` 注入以下规则块到 prompt 上下文：

```
<WST_世界状态>
时间：xxx
区域：xxx
在场角色+BUFF：xxx
...

[追踪规则]：
1. 仅追踪女性角色，男性角色不出现在任何字段中。
2. 用户扮演的角色「xxx」不追踪，任何字段不出现。
3. 在场角色 = 当前场景（最近消息对话场景）中出现的所有女性角色。
4. 不在场角色 = 之前出现过但当前不在主角所在场景的女性角色。
   格式：角色名-在做什么（≤10字）。当前场景中的角色绝不能误判为不在场。

[世界书角色]：xxx (如有)
[好感度系统]：xxx

请在回复末尾用 <S-summary> 标签输出更新后的世界状态。
</WST_世界状态>
```

### S-summary 格式

AI 需要在回复末尾输出：

```xml
<S-summary>
时间：2024年7月15日16时00分
区域：蒙德城·天使的馈赠酒馆
在场角色+BUFF：琴（微醺）、芭芭拉（开心）、丽莎（正在调制饮料）
不在场角色：优菈-在野外巡逻、安柏-在城门口执勤
处女膜状态：琴：完整、芭芭拉：完整、丽莎：完整、优菈：完整
做爱次数：琴：0次、芭芭拉：0次、丽莎：0次、优菈：0次
当前好感度：琴：78（信任）、芭芭拉：60（友好）、丽莎：45（普通）
身体外貌：琴：穿着常服，马尾有些松散。芭芭拉：穿着牧师服，面带微笑。丽莎：穿着紫色魔法袍，慵懒地靠在吧台。
重要记忆点：
- 琴：与主角在深渊教团袭击中并肩作战|被主角从深渊使徒围攻中救下
- 芭芭拉：主角帮助她找到了失踪的唱诗班孩子|在教堂初次见面时为主角治疗伤口
</S-summary>
```

## 🧩 静默总结机制

除了从 AI 回复中解析 `<S-summary>`，本扩展还会在每次 AI 回复完成后触发**静默总结**：

1. 取最近 15 条聊天记录
2. 构建包含全部规则的系统提示
3. 调用 `generateQuietPrompt()`（静默 API 调用，不显示在聊天界面）
4. 解析返回的状态文本
5. 合并并保存

这确保了即使 AI 忘记输出 `<S-summary>`，状态也能得到更新。

### 静默总结的 Prompt 结构

```
[System] 你是世界状态追踪器。根据聊天记录提取当前世界状态。只输出状态，不要解释。

[User] 聊天记录：
角色A：...
角色B：...
（最近15条）

请按以下格式输出当前世界状态：
时间：...
区域：...
在场角色+BUFF：...
不在场角色：...

★★★ 核心规则 ★★★

【规则0：仅追踪女性角色】
   所有字段仅记录女性角色信息。男性角色不出现。

【规则0.5：排除用户角色】
   「用户名」是用户扮演的角色，无论男女，任何字段不出现。

【规则1：在场/不在场的核心判断标准】
  在场角色 = 查看最近几条消息的对话场景，该场景中出现的所有女性角色。
  判断方法：如果角色在说话、被对话、有动作描写，她就在场。
  关键：主角当前所处场景就是"在场"场景。场景中所有女性均是在场角色。
  示例：
    琴和主角在办公室对话，芭芭拉进来打招呼 → 在场=琴、芭芭拉
    主角和琴在战斗，芭芭拉在远处施法 → 在场=琴、芭芭拉
    主角在酒馆，回想昨天和琴的对话 → 在场=无（琴不在场景中）

【规则2：不在场角色】
  之前出现过但当前不在主角所在场景的女性角色。
  当前场景中出现的角色绝不能被误判为不在场！

【输出前自检】
  □ 是否所有在场角色都正确识别了？
  □ 当前场景中的角色是否被错误分到"不在场"？
  □ 是否排除了用户角色和所有男性角色？
```

## 💾 数据存储

### localStorage

```
key: wst_state_<聊天文件名>
value: JSON {
  time: string,
  location: string,
  present: string,
  absent: string,
  hymen: string,
  sexCount: string,
  affection: string,
  appearance: string,
  memories: { "角色名": ["记忆1", "记忆2", ...] }
}
```

- 每个聊天文件独立存储，互不干扰
- 所有字段均经过 `filterUserFromState()` 过滤，确保不包含用户扮演角色

### 内存

- `MESSAGE_STATES` (WeakMap) — 每条消息 ↔ 独立状态快照（历史消息用），避免所有卡片同步更新
- `PROCESSED` (WeakSet) — 已处理的消息 DOM 元素
- `lastStateSentHash` — 避免重复注入

## 🛡️ 用户角色排除机制

### 双层防护

1. **Prompt 层面**：在注入给 AI 的规则中明确指示不追踪用户角色
2. **代码层面**：`filterUserFromState()` 在保存前清理所有字段

### 识别用户角色名

```
优先级：
1. SillyTavern context.name1（用户显示名）
2. context.persona.name（用户 persona 名）
3. 如都不是，跳过过滤（''）
```

会在以下字段中剔除用户角色名：
- 在场角色+BUFF
- 不在场角色
- 重要记忆点

## 🧪 技术架构

| 技术选型 | 说明 |
|---------|------|
| 入口方式 | SillyTavern 扩展系统（manifest.json → index.js + style.css） |
| 事件系统 | `SillyTavern.getContext().eventSource` ST 内部事件总线 |
| 状态存储 | `localStorage`（key 含聊天文件名）+ WeakMap（消息级快照） |
| DOM 操作 | 原生 JS（兼容旧浏览器，不使用可选链/箭头函数/模板字符串） |
| JS 语法 | ES5 兼容（var、function、无箭头函数、无 let/const） |
| AI 注入 | `setExtensionPrompt(key, text)` 追加到 prompt 上下文 |
| 静默调用 | `generateQuietPrompt()` 后台调用 LLM |

### 兼容性

- ✅ 纯 ES5 语法，兼容各种酒馆版本
- ✅ 事件系统 + MutationObserver 双重兜底
- ✅ DOM 选择器容错（`.mes` / `.mes_text` 多版本兼容）
- ✅ HTML 实体多重解析（`&lt;` → `<`, `&gt;` → `>`, `&amp;` → `&`）
- ✅ S-summary 多模式匹配（标准/转义/交叉实体）

## 🐛 故障排查

| 问题 | 检查 |
|------|------|
| 卡片不出现 | 检查酒馆控制台是否有 `[WST]` 日志；确认扩展已启用 |
| S-summary 未被提取 | 检查 AI 回复中标签格式是否标准（`<S-summary>...</S-summary>`） |
| 在场角色判断不准 | 检查世界书角色配置是否完整；尝试手动编辑修正 |
| 状态不注入 Prompt | 检查控制台 `[WST] ✅ 状态已注入到Prompt` 日志 |
| 静默总结失败 | 检查 `generateQuietPrompt` 是否被其他扩展拦截；查看控制台错误 |
| 用户角色未被排除 | 确认酒馆中 `name1` 或 persona 名称设置正确；检查控制台是否有 `[WST] 👤 从聊天记录中检测到用户名` |
| 不在场角色中出现在场角色 | 代码层安全网会自动清理，检查控制台 `[WST] 🧹` 日志确认是否生效 |
| 不在场角色中出现泛称（七神等） | 同上，`isGenericEntry()` 会自动剔除；如仍出现说明模型输出过于离谱，可手动编辑 |
