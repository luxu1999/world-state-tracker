# 🌍 世界状态追踪器 (World State Tracker)

> SillyTavern 角色扮演扩展 — 自动追踪世界状态，让 AI 记住每个角色的位置、状态、记忆与好感度。

## ✨ 功能

- 🤖 **自动提取状态** — AI 回复末尾输出的纯文本状态（9 字段）自动提取并存储；兼容 HTML 注释 `<!-- WST -->` / `<S-summary>` 双保险
- 📋 **可折叠状态卡片** — 仅最新 2 条消息（AI+用户）显示卡片，旧卡片自动清除
- ✏️ **手动编辑** — 点击任意字段直接修改，立即生效
- 🔄 **静默总结** — 用户发消息后触发总结获取演化状态；AI 回复后走纯文本状态提取；scan() 在最后AI消息无状态/版本清理后自动用 AI 总结补全 B
- 💾 **chatMetadata 持久化** — 数据跟随聊天对象（对标 st-memory-enhancement），切换聊天不污染
- 🔗 **状态继承链（B→b）** — AI 消息卡片显示 B（标签提取）；用户消息卡片显示 b = B 经用户事件线性演化（b ≠ B）
- 📖 **世界书集成** — 自动读取世界书角色列表和好感度系统
- 🧠 **智能记忆管理** — 重要记忆自动评分排序，每人最多 6 条，每条 ≤70 字
- 🔇 **隐藏原始标签** — 从消息显示中移除原始状态文本，保持界面整洁
- 👩 **仅追踪女性角色** — 所有字段（在场/不在场/状态/记忆等）仅记录女性角色
- 🚫 **排除用户角色** — 用户扮演的角色（即使为女性）不出现在任何追踪字段中
- 🛡️ **多层安全网** — 自动清理在场/不在场矛盾，剔除泛称条目，版本更新自动清理旧数据

---

## 📥 安装

1. 下载 `world-state-tracker` 文件夹
2. 放入 SillyTavern 的 `data/default-user/extensions/` 目录
3. 在酒馆扩展面板中启用「世界状态追踪器」
4. 重新加载酒馆

> ⚠️ 如果你在使用旧版本预设中的 Regex 脚本或提示词注入来做状态追踪，请在启用本扩展前关闭它们，避免重复注入。

## 🧠 状态继承逻辑（v3.8.0+）

### 核心概念

```
#102 AI回复 → 状态(A)    ← AI回复末尾输出的纯文本状态（9字段）定义初始状态
#103 用户消息 → 状态(a)   ← 在A基础上经用户故事演化（静默总结）
#104 AI回复 → 状态(B)    ← 在a基础上经AI回复事件演化（标签提取）
#105 用户消息 → 状态(b)   ← 在B基础上经用户故事演化（静默总结）
...依此类推
```

| 继承关系 | 说明 |
|---------|------|
| **a 继承 A** | 用户消息包含故事推进 → 触发静默总结 → 状态在 A 基础上演化，a 与 A **不同** |
| **B 继承 a** | AI 回复叙事后输出纯文本状态（9字段）→ 提取合并为 B |
| **b 继承 B（核心）** | 用户下一轮输入推动故事 → 静默总结将 B 线性演化出 b，**b ≠ B**（时间推进/位置移动/角色加入离开/好感变化等） |

> ⚠️ **核心约束（REQUIREMENTS.md 2.2）**：相邻两个卡片（B 和 b）的内容不能相同；每个新卡片必须在前一个卡片基础上有可观察的变化，且变化必须符合聊天内容的线性逻辑。

### 卡片显示规则

仅最新 **2 条消息**（最新 AI 回复 + 最新用户消息）显示状态卡片，历史消息的卡片自动清除。每聊天只保存 **2 个状态快照**（最新 AI 的 B + 最新用户的 b），新状态产生时旧状态被顶替（替换而非追加），切换聊天互不污染。

```
...旧消息...
#102 AI → [无卡片]
#103 用户 → [无卡片]
#104 AI → 状态追踪(B)  ← 保留
#105 用户 → 状态追踪(b) ← 保留
```

## 🧠 工作原理

### 数据流（v3.8.0+）

```
┌────────────────────────────────────────────────┐
│  用户发消息                                       │
│  ├─ CHAT_COMPLETION_PROMPT_READY 注入状态到Chat数组 │
│  └─ USER_MESSAGE_RENDERED → 渲染b卡片+静默总结演化  │
└──────────────────┬─────────────────────────────┘
                   ▼
┌────────────────────────────────────────────────┐
│  AI 回复（末尾含纯文本状态）                       │
│  ├─ GENERATION_ENDED / CHARACTER_MESSAGE_RENDERED  │
│  ├─ extractStateFromText() 纯文本提取状态        │
│  └─ mergeState() 合并为 B 快照                    │
└──────────────────┬─────────────────────────────┘
                   ▼
┌────────────────────────────────────────────────┐
│  保存到 chatMetadata.wst_state（跟随聊天对象）       │
│  + 双快照 wst_ai_state(B) + wst_user_state(b)      │
└──────────────────┬─────────────────────────────┘
                   ▼
┌────────────────────────────────────────────────┐
│  渲染卡片（仅最后2条消息）                          │
│  蓝色头部 + 粉色内容区，可折叠                      │
└────────────────────────────────────────────────┘
```

### Prompt 注入（对标 st-memory-enhancement）

本扩展使用 `CHAT_COMPLETION_PROMPT_READY` 事件**直接操作 `eventData.chat` 数组**注入状态 Prompt（回退方案：`setExtensionPrompt()`）。

### 事件驱动

| 事件 | 行为 |
|------|------|
| `CHAT_COMPLETION_PROMPT_READY` | 注入世界状态到 Chat 数组（对标 st-memory-enhancement） |
| `CHARACTER_MESSAGE_RENDERED` / `GENERATION_ENDED` | AI 消息 → 提取纯文本状态作为 B（兼容 `<!-- WST -->` / `<S-summary>`） |
| `USER_MESSAGE_RENDERED` / `MESSAGE_RENDERED` | 用户消息 → 渲染 b 卡片并触发静默总结（b = B 经用户事件演化，b ≠ B） |
| `CHAT_CHANGED` | 切换聊天 ID，重新扫描，无状态时自动注入首次回溯指令 |
| `MESSAGE_UPDATED` | 消息编辑后重新扫描 |
| MutationObserver（兜底）| DOM 变化时扫描（事件系统不可用时） |

## 🔧 AI Prompt 注入规则

本扩展在每次 AI 生成前注入以下规则块到 prompt 上下文：

```
<WST_世界状态>
时间：xxx
区域：xxx
在场角色+BUFF：xxx
...

[追踪规则]（v3.8.5 最小变化原则）：
0. 核心原则：最小变化！每个字段仅在本轮正文有明确证据时才更新，否则必须严格复制上一状态，禁止凭空修改。
1. 仅追踪女性角色，男性角色不出现在任何字段中。
2. 用户扮演的角色「xxx」不追踪，任何字段不出现。
3. 时间：精确到分钟，在上一轮基础上按事件推断推进（对话→几分钟、战斗→几十分钟、长途旅行→数小时或数天；无流逝则不变；用户给定以用户为准）。
4. 区域：仅明确移动时更新，层级格式：中国-湖北省-武汉市-武昌区-友谊大道-湖北大学 或 魔王城堡-卧室-床上。
5. 在场角色+BUFF：仅明确加入/离开/获得BUFF时更新，格式：琴（回溯魔法）。BUFF仅指永久/临时正向/负向收益，伤口/心态/衣服不算。
6. 不在场角色：仅随在场角色变化更新。
7. 处女膜状态：仅破处性交时更新。
8. 做爱次数：仅性交且射精时+1。
9. 当前好感度：仅言行明确体现好感变化时更新（有世界书系统则参照）。
10. 重要记忆：仅新事件追加，每角色≤6条合计≤70字（第7条替换最轻的一条）。
11. 身体外貌：仅换装/脱衣/发型变化时更新，严禁凭空写裸体或换衣。

[世界书角色]：xxx (如有)
[好感度系统]：xxx

[世界状态输出指令]：回复正文结束后，必须在末尾用纯文本追加当前世界状态，9个字段每行一个，直接输出字段名+值。禁止使用任何HTML注释、标签或<summary>包裹，禁止省略任何字段。

正确示例（最小变化输出）：
时间：第1天 15:30
区域：蒙德城·天使的馈赠
在场角色+BUFF：琴（回溯魔法）|芭芭拉（治疗中）
不在场角色：诺艾尔-在骑士团值班
处女膜状态：完好
做爱次数：0次
当前好感度：友好(65/100)
身体外貌：琴：琴骑士制服破损/金发散乱遮脸/下唇血痂干涸
重要记忆点：
- 琴：帮助旅行者解决风魔龙危机|欠旅行者一个人情

⚠️ 若省略状态输出，世界状态将无法更新，角色记忆会丢失！
</WST_世界状态>
```

首次使用时（状态为空但有聊天历史），自动注入**首次回溯指令**，要求 AI 根据已有剧情推导世界状态。

**聊天记录读取规则（v3.8.3+，REQUIREMENTS.md 2.5）**：
- **首次读取**：读取全部聊天历史（不只最后 N 条），按「最近 N 条 AI 消息 / 最近 20 条用户消息 / 最近 50 条消息」分组标注后交给 AI 总结生成初始状态 B
- **后续读取**：基于上一状态 + 新消息增量演化（`slice(-30)`），不重扫全部
- **记忆增强**：状态经 `CHAT_COMPLETION_PROMPT_READY` 注入 Prompt，作为 AI 短期记忆

## 💾 数据存储（v3.8.0+ 对标 st-memory-enhancement）

### chatMetadata（主要存储）

```
ctx.chatMetadata.wst_state          ← 当前状态（= 最新快照，用于 Prompt 注入）
ctx.chatMetadata.wst_ai_state       ← 最新AI消息快照（B）
ctx.chatMetadata.wst_user_state     ← 最新用户消息快照（b）
ctx.chatMetadata.wst_version        ← 版本号（变更时自动清理全部旧数据并重新记录）
```

**双快照模型（v3.8.0+）**：每聊天仅保存 2 个快照（最新 AI 的 B + 最新用户的 b），新状态产生时旧状态被顶替（替换而非追加）。v3.8.0 起移除逐消息快照 `wst_msg_states`，旧数据在版本变更时自动清除。

**优势**：数据跟随聊天对象，ST 切换聊天时自动加载/保存，**不存在跨聊天 key 碰撞污染问题**。

### localStorage（回退兼容）

旧格式 `wst_state_<聊天ID>` 在首次加载时自动迁移到 chatMetadata，随后删除。

### 消息识别

使用 `msgEl.getAttribute('mesid')` 精确定位消息在聊天数组中的索引（O(1)），不回退到文本匹配（保留兼容）。

## 🛡️ 安全机制

### 跨聊天隔离（v3.3.4+）

- 数据存在 `chatMetadata` 而非独立的 localStorage key
- chatMetadata 跟随聊天对象，ST 原生隔离
- 版本号标记：每次更新自动清理旧数据重新扫描

### 代码层安全网

- `sanitizeState()` — 在场角色自动从不场中剔除（模糊匹配）
- `isGenericEntry()` — 检测并剔除"七神""众人""各国角色"等泛称
- `filterUserFromState()` — 保存前过滤用户扮演角色

### 用户角色排除

1. **Prompt 层面**：AI 规则中明确指示
2. **代码层面**：`filterUserFromState()` 保存前清理
3. **识别路径**：`ctx.name1` → `ctx.persona.name` → 聊天记录 `is_user` 消息

## 🐛 故障排查

| 问题 | 检查 |
|------|------|
| 卡片不出现 | 检查酒馆控制台是否有 `[WST]` 日志；确认扩展已启用 |
| 状态未被提取 | 检查 AI 回复末尾是否输出「时间：xxx」开头的纯文本状态；v3.8.4 起指令已改为纯文本格式 |
| 跨聊天状态污染 | v3.3.4+ 已改用 chatMetadata，确认版本号；首次加载会自动清理 |
| 状态不注入 Prompt | 检查控制台 `Chat数组注入` 日志；如用回退模式看 `ExtensionPrompt注入` |
| 静默总结返回故事续写 | v3.3.0+ 已加直接 API 调用回退；手机端异步不可靠时依赖 AI 主回复纯文本输出（v3.8.4+） |
| 重载后卡片消失 | v3.8.0+ 双快照持久化；检查 `wst_ai_state` / `wst_user_state` 是否正常保存 |
| 用户角色未被排除 | 确认酒馆中 `name1` 或 persona 名称设置正确 |
| 记忆编辑后为空 | 编辑时格式需以 `- ` 开头，如 `- 琴：记忆1\|记忆2` |
| 不在场角色中出现泛称 | `isGenericEntry()` 会自动剔除；如仍出现说明模型输出过于离谱 |
